# 缺口补足（仅异常路径）

正常查询、配置和执行继续使用业务目录及已支持接口。不要因为存在动态工具就在每次操作前扫描宿主，不将缺口检查设为默认准备调用或保存进快捷任务。

只有本轮已有具体证据时才进入：常规目录完整查询仍未覆盖目标、接口明确报告成员或签名变化，或入口已登记但当前不能使用。先保留真实失败类别和查询范围；单次拼写错误、空查询或猜测不是契约漂移。

先按需搜索能力摘要并读取命中项的单项契约，区分宿主声明、桥支持、当前上下文与执行结果。若业务契约已足够，立即回到业务接口；不继续检查内部实现。

确实需要检查结构时，再发现独立的缺口诊断工具，携带本轮具体依据与缺口类别，只查看相关根对象、路径和必要成员页。不得漫游整个对象图、主动求值属性、调用未知 getter、导入模块、构造对象或尝试执行表达式。

字段和方法存在、参数名可读，都不证明语义或当前可调用。参数默认值、写入约束、任务副作用与结果含义仍以可核验契约为准；未得到语义依据的部分明确记录为待适配，不用猜测调用拼出成功结果。不得借动态入口绕过已有明确限制。

完成缺口定位后退出探索，复用已支持路径，或者准确说明缺失的适配、初始化条件及证据。普通业务不持续保留内部结构资料，也不把诊断过程扩展成未经请求的修改、安装或运行。

确需动态执行补足时，先取得桥根据本轮真实目录缺口签发的凭据，再用相关现场成员凭据生成动作预览。仅凭模型自写的缺口说明不能执行。核对预览的对象、方法语义、参数、字段原值与新值，符合本次用户目标和授权后才提交一次对应写入入口。

预览不执行；执行时不得替换参数或复用旧票据。桥重连、对象变化、版本冲突、过期或票据已使用时重新检查，不盲目重发。方法返回只证明调用返回，不能当作任务接纳或业务完成；执行中超时或异常先核实现场。已有专用接口和明确限制仍然优先，不能借动态入口绕过。

动态字段修改的持久性以返回为准：运行时原位修改不等于保存配置；官方条件保存须核对修订与回读。动态调用和修改只处理本轮具体缺口，禁止作为普通准备步骤、连续探索习惯，或保存到快捷任务、定时任务与长期工作流。
