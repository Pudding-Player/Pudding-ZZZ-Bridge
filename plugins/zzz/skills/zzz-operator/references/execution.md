# 提交、运行与停止

从当前能力说明核对对象、影响、所需初始化和返回含义。只查询或配置时不准备游戏；真正执行时沿用所选实例和配置组的有效设置，只核对本次动作需要的前提。

一条龙的运行接纳说明宿主已经接受异步提交，不等于应用已执行完毕，也不能仅凭接纳回执认定已经切到目标账号或进入游戏。普通启动到真实接纳后结束本轮，不继续查日志、截图或运行状态来制造额外进展。

当前桥可以读取运行上下文和最近结果，没有专用的业务完成等待或事件订阅入口。用户要求等结果时，先核对外层任务系统能否基于本次应用记录表达受控等待；无法闭合时说明缺口，不编造等待能力，不用固定等待或不断调用模型轮询代替业务完成。

运行中、暂停、停止与后台线程退出不同。读取到了暂停状态，不代表当前桥提供暂停或恢复操作；用户要求暂停时不能悄悄改成停止。已有任务占用上下文时不叠加、不擅自停止或另起宿主。

停止回执可能只确认宿主运行状态机收口。观察窗口内没有确认就报告未知；即使逻辑状态已停止，也不能保证后台线程和游戏内动作已经全部结束。不要通过关闭界面或杀进程来伪造停止确认。

明确未提交只说明拒绝原因，不编造重试次数或连接故障。排队撤销、执行中超时和回执丢失按当前证据区分；可能已执行时不重复运行或保存，先只读核实。
